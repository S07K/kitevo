# Getting help with Kitevo

Thanks for using or contributing to Kitevo. Here is where to go for what.

| I want to... | Go to |
| --- | --- |
| Ask a question about running or developing Kitevo | [GitHub Discussions](https://github.com/S07K/kitevo/discussions) |
| Report a bug | [Open a bug report](https://github.com/S07K/kitevo/issues/new/choose) |
| Suggest a feature | [Open a feature request](https://github.com/S07K/kitevo/issues/new/choose) |
| Report a security vulnerability | [Private vulnerability reporting](https://github.com/S07K/kitevo/security/advisories/new), see [SECURITY.md](./SECURITY.md) |
| Report a Code of Conduct concern | See [CODE_OF_CONDUCT.md](./CODE_OF_CONDUCT.md#enforcement) |

## Before you ask

- Read the [README](./README.md), especially [Getting started](./README.md#getting-started).
- `.env.example` documents every environment variable and its gotchas.
- [DEPLOY.md](./DEPLOY.md) covers production deployment, database migrations and
  OAuth/webhook setup.
- [CLAUDE.md](./CLAUDE.md) explains the architecture and the reasoning behind
  non-obvious conventions.
- Search existing issues and discussions; your question may already be answered.

## When you ask

Include what you tried, what you expected, what happened, your Node.js version and
the commit you are on. Never paste API keys, tokens, passwords or `.env` contents.

Support for the open-source project is best effort. There is no
paid support channel for the open-source project.
